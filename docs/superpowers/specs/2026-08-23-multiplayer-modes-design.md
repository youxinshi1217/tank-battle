# 多人模式设计：双人对战（PVP）与双人 PvPvE

日期：2026-08-23
范围：在既有单人波次玩法之上，新增**双人对战（PVP）**与**双人 PvPvE** 两大玩法入口，并引入"系列赛(N局) + 单局(round) + 局内积分"的统一对局模型。

## 背景与动机

单人模式已完成（波次通关 = 胜利、玩家被摧毁 = GAME OVER）。项目需要扩展出多人对战玩法以提升展示完整性。经与用户多轮规则收敛，最终定稿的单局判定如下（**全部无时限**）：

- **单人**：每局打满当前关波次，清空敌人 = 玩家胜；被摧毁 = 敌胜。
- **PVP**：一方玩家被摧毁 = 该玩家负该局。
- **PvPvE**：友方清空全部敌方 AI = 友胜；友方全员被摧毁 = 敌胜。

**判定边界（消除歧义）**：
- PVP 中玩家被摧毁的归属：**该局负者=被摧毁方**，胜局数记给对方**（与谁开的枪无关）**；但"击败对方玩家 +1 分"仅在被摧毁方是被对方玩家亲手击杀时才加（记分仍需归因）。
- PVP 双玩家**同一帧互相摧毁**（反弹/对杀）：该局作废、双方都不记胜局，直接**重开该局**，直至某局有人独亡。
- PvPvE 中 **P2 恒在场**（双子阵营），不存在"P2 缺席"选项；菜单"P2 加入与否"仅适用于通过选择模式时的流程，PvPvE 内 P2 始终参战。

系列赛胜负由"先达成胜局数"决定，**局内积分只作滚动记分牌，不参与任何胜负判定**（该口径已在评审中明确，消除"积分多者胜"与"清空/团灭即定胜负"之间的冲突）。

## 关键现状（已核实）

- `entities/bullet.py`：`owner` 字段为 `"player"/"enemy"`，仅在 `owner == "enemy"` 时用敌弹速；其余字符串一律走玩家弹速。**可直接传 `"p1"/"p2"` 而不改 bullet（默认 fallback 为玩家速度）**。
- `entities/player_tank.py`：`handle_input(keys, dt)` 内部硬编码 WASD+J（`pygame.key.get_pressed()`）。
- `core/game_state.py`：`GameState` 枚举仅 5 值；项目硬约束"不新增 GameState 值"。局间子状态须放在 Game 层内部变量，不另建枚举。
- `core/score_manager.py`：纯数据层（`current_score/kill_count/stage_score/...`），无判断逻辑，易扩展。
- `ui/menu.py` + `main.py._mode_screen()`：双人对战 / PvPvE 目前为 `enabled=False` 占位。
- `core/settings.HELP_TEXT` 已预告键位：P1 = WASD + J，P2 = 方向键 + 空格。

## 硬约束（不可破坏）

- **不新增 GameState 枚举值**；局间流转用 Game 层子状态变量 + PLAYING 状态内处理（仿既有 Stage Transition 先例）。
- **不改冻结文件**：`entities/player_tank.py`、`entities/bullet.py`、`core/collision.py`、`core/tank_physics.py` 等。P2 输入通过**新增子类覆写 handle_input** 实现，不触碰 player_tank.py。
- 敌方 AI（`enemy_tank.py`）**不应被友军/玩家双方友军规则污染**；阵营划分落在 Game 层与子弹 owner 判定，不改敌人逻辑。
- 失效/差异项（评审已剔除）：**"敌方阵营内讧→判友方胜""+2分/不扣分"条款**因敌方 AI 不会互相开火、且积分已与胜负解耦，本阶段冻结不实现。

## 统一对局模型

```
系列赛(Match) = N 局，先赢 W = ⌈N/2⌉ 局者胜全部
   └ 每局(Round) = 当前关卡的完整波次/对抗流程
        └ 局内积分(RoundScore) = 该局内击杀+流程奖励（只作展示）
        └ 单局归属：由各模式规则判定
```

**系列赛参数表**（写入新增 `core/match_config.py`）：

| 模式 | 局数 N | 胜局 W | 敌人来源 | 友军伤害 |
|---|---|---|---|---|
| 单人-简单 | 5 | 3 | 该关全波次 | — |
| 单人-普通 | 5 | 3 | 该关全波次 | — |
| 单人-中等 | 7 | 4 | 该关全波次 | — |
| 单人-困难 | 9 | 5 | 该关全波次 | — |
| PVP-可选局数 | 5/7/9/11/13 | 3/4/5/6/7 | 纯 P1 vs P2 对抗（无 AI 敌人） | — |
| PvPvE-按难度 | 5/5/7/9 | 3/3/4/5 | 该关全波次 | 开启 |

> **PVP 范围修订（评审定稿）**：PVP 不再提供"可选中立 AI"（原 0~2 个中立 AI 方案已移除，避免额外配置与中立目标复杂度），为纯 P1 vs P2 双人对抗；对局数由玩家在双人模式页选择（5/7/9/11/13，先赢 ⌈N/2⌉）。**开发顺序调整为：先做 PvPvE，后做 PVP。**

> **单局敌人来源（已定稿 = 波次清关制）**：单人 / PvPvE 每一局复用当前选定 stage 的完整波次流程（WaveManager + 该关 `wave_config`），清空全部波次 = 该局胜，玩家/友方全灭 = 该局负。**"小/中/重敌人类型"本次不实现**（现有 `enemy_tank.py` 仅 small 单型），作为独立后续任务。
>
> **难度档在局制下的作用（已定稿）**：局制中难度**仅决定系列赛局数**（简单/普通 5 局、中等 7 局、困难 9 局），不影响敌我强度——`DIFFICULTY_PROFILES` 的波次人数/敌数上限/射速倍率尚未接线；波次人数为**全关卡、全难度统一**的手动配置。
>
> **关卡流程（已定稿）**：单人 / PvPvE 均沿用"选关 → 选难度"流程；全模式**任意关卡直接可选**，无前置通关解锁限制。`N` 局系列赛在**选定的单关**内进行（每局清该关全波次）。

## 模块与文件变更

### 新增 `core/match_config.py`
- `MATCH_RULES`：模式 × 难度 → `{rounds, win_rounds, can_add_ai, friendly_fire, ai_cap}`。
- `WIN_ROUNDS = ceil(N/2)` 统一推导，避免硬编码胜局数。
- 中央化所有魔法数字（人数、胜局、可加 AI 数）——契合项目"参数集中"偏好。

### 新增 `entities/player2_tank.py`（PvP / PvPvE 的 P2）
- `class Player2Tank(PlayerTank)`：仅覆写 `handle_input(keys, dt)`，将方向键 + 空格映射为 throttle/steering，其余继承（物理/碰撞/弹药/道具/渲染全复用，不触碰冻结文件）。
- 提供渲染识别（如车身色相偏蓝），便于区分 P1/P2。
- P1 沿用现 `PlayerTank` 的 WASD+J。

### `main.py`（Game 层，主要改动点）
- 新增运行子状态：`match_mode`（None/`'pvp'`/`'pvpe'`）、`current_round`、`p1_round_wins/p2_round_wins`（PVP）、`friendly_round_wins/enemy_round_wins`（PvPvE）、`round_over`。
- `_load_stage` / `update` 内的"玩家被摧毁 → GAME OVER"路径改为按 mode 分流到 `_handle_player_destroyed(shooter)`：
  - 单人：维持结局→但升级为"该局负 → 计胜局 → 下一局/系列结算"。
  - PVP：该玩家负该局 → 对方胜局数 +1 → 下一局/系列结算。
  - PvPvE：友方存活数 -1；若友方全灭 → 敌胜 → 下一局/系列结算。
- 子弹 owner 扩展：开火时传入 `"p1"` / `"p2"` / `"enemy"`，碰撞表据此判定归因与友军伤害。
  - **敌方（波次敌人）子弹需对 P1 与 P2 都判撞**（现碰撞分支仅查 `self.player_tank`，[main.py L494-504](file:///c:/Users/32857/Desktop/tank_game/main.py#L494-L504)），多人模式下扩展为同时遍历两位玩家。
  - **护盾统一免疫伤害**：P1/P2 的护盾（`PlayerTank.handle_enemy_hit`）对敌方子弹与友军子弹均生效——友军伤害命中持盾方同样被无害化，不消耗护盾时间。
- 系列结算页：新增"返回菜单"（复用既有结果 overlay 样式），显示每局胜局比。

### `bullet.py` owner 扩展（不改文件，仅约定取值）
- 沿用现有 owner 字符串机制；`"p1"/"p2"` 落入非 `"enemy"` 分支走玩家弹速，无需改 bullet 源码。**友好地复用现有字段，零改动。**

### `menu.py` / `_mode_screen()`
- 启用"双人对战 / PvPvE"，各进入独立配置（AI 个数/难度、P2 是否加入、难度档）页后开赛。

### HUD / 表现
- 多人局间覆盖层：回合倒计时/回合文字（"ROUND 3/9 · P1 2 · P2 1"），复用既有 result overlay 绘制方式。

## 计分规则（与胜负解耦，仅记分牌）

| 事件 | 单人 | PVP | PvPvE |
|---|---|---|---|
| 击败敌方坦克（波次敌人） | +1 | — | 友方合计 +1 |
| 击败对方玩家 | — | +1 | — |
| 友军伤害（P1 杀 P2） | — | — | 不加不计（明确：无 ± 分） |

> 任一阵营胜局数先到 W 者赢系列赛；奇数 N 保证不可能平局（必有单胜方）。

## 验收标准

1. 三种模式经由菜单分别进入，能打完 N 局、按 W 决出系列胜者并回到菜单。
2. PVP **纯双人对抗**（无 AI 敌人），一方被摧毁即该玩家负该局。
3. PvPvE 友军子弹对友军有伤害判定、但击杀队友不计分；**友方团灭即敌胜**。
4. 全程不新增 GameState 枚举、不改冻结文件（player_tank/bullet/collision/tank_physics）。
5. 当 `ITEM_SYSTEM_ENABLED=False` 时，多人模式行为不受影响（回归既有逻辑）。

## 风险与开放项

- **🔴【已定稿】单局"敌人来源"**：采用**波次清关制**（复用该关 wave_config 全波次），"小/中/重"敌人类型本阶段不实现。见参数表注释。
- **🟠【已定稿】难度在局制下仅决定系列局数**，`DIFFICULTY_PROFILES` 强度倍率尚未接线（全关卡、全难度波次人数统一）；见参数表注释。
- **🟠【已定稿】关卡/解锁**：单人 / PvPvE 沿用选关流程；**全模式任意关卡直接可选，无解锁限制**；`N` 局在该关内进行；见参数表注释。
- **🟠【已定稿】PVP 无中立 AI，PVP 目标机制不适用**：PVP 为纯玩家对抗，不生成 AI；"敌方/中立 AI 目标 = 追最近玩家"规则转由 **PvPvE 波次敌人**使用（双方玩家在场时取距敌人最近者），已有 `EnemyTank.update(dt, player_pos)` 单目标接口在 main.py 层传入最近玩家即可。
- **🟡【待核实】友军伤害归因范围**：普通弹走 `Bullet`、霰弹走 `ShotgunPellet`；PvPvE 友军判定须将 **pellet 也纳入 `owner` 归因**，否则 P1 霰弹命中 P2 不判友军伤害。
- **冻结文件是否真的"冻结"**：项目记忆将 player_tank.py 列为冻结，但实测其已被多轮扩展（道具/护盾/尾焰均落入其中）。本设计以"子类覆写"规避改动；若对账发现必须在其内加按坦克 id 的键位参数化，需另行提请用户豁免。
- **"小/中/重"敌人类型为后续独立任务**：现有 `enemy_tank.py` 仅 small 单型，本次不实现的阵容扩张不在多人模式范围内；如需差异化敌人（体型/速度/火力）另立专项。
- **PvPvE 敌人可能同时被 ≥2 名玩家瞄准击杀**：既有无 HP 判定天然支持多对一，无需扩展。
